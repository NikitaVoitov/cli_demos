# Agent instructions

This repo turns real AI-client sessions against Splunk Cloud into interactive demo pages. The design is
`docs/demo_pipeline_architecture.md`; the use cases are `docs/headless_use_case_matrix.md`.

**Before building, recording, updating, or narrating a demo, read `.agents/skills/demo-author/SKILL.md` and follow it.**
Cursor, Codex, and Copilot may load it automatically; Claude Code has to open it from that path.
Setup for a new machine is in `README.md`; `python3 scripts/doctor.py` reports what is missing.

## Layout

- `scenarios/<id>/scenario.yaml`: what gets recorded and narrated. `content.yaml` and `how-it-works.md`: what visitors read.
- `scenarios/<id>/artifacts/`: generated by the pipeline only (cast, transcript, narration audio and captions, screenshots).
- `pipeline/`: Python steps run as `.captures/venv/bin/python -m pipeline.<capture|post|transcript|narrate>`.
- `recorder/`: capture home, client configs, hint files, and `voice.yaml` (the house narration voice).
- `scripts/`: capture environment (`ce01_capture.py`), stack profiles, seeders, screenshot and login helpers, `doctor.py`.
- `apps/hub/`: the Vite + React page that plays the demos.
- `.captures/`: raw takes and caches. Git-ignored; never commit from it.

## Rules

- Keep chapter IDs in `scenario.yaml` and their labels in `content.yaml` in step. Add or remove both in the same change.
- Narration text lives in `scenario.yaml` `narration.lines`. After changing a line, a chapter time, or the voice, rerun `python -m pipeline.narrate scenarios/<id>` and commit its outputs.
- No secrets, usernames, IPs, or real stack hostnames in anything committed.
- Don't push to `main` or write to Sanity.
